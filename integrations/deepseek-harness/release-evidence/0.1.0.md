## Real-model structural acceptance

The real DeepSeek run must use a unique marker in the user prompt and request the final token `DSH_REAL_MODEL_SKILL_SECURITY_GUARD_OK`. After the run, verify the uncompressed JSONL from a source checkout:

```powershell
$env:DSH_SMOKE_HOME = "D:\absolute\path\outside-the-repository"
$env:DSH_SMOKE_MARKER = "the-unique-marker-used-in-the-prompt"
$env:DSH_SMOKE_FINAL_TOKEN = "DSH_REAL_MODEL_SKILL_SECURITY_GUARD_OK"
$env:DSH_SMOKE_EXPECTED_SHELL = "pwsh"
node integrations/deepseek-harness/scripts/verify-real-smoke.mjs
```

The verifier fails unless one and only one session has the marker, the `skill` result contains the packaged safety instructions, the later shell call uses `profiles/headless/node_modules/dsh-skill-security-guard/assets/scripts/scan.py`, the structurally linked result is A/100, and the final assistant message appears after that result. It refuses a smoke home inside the repository and never prints raw session content.
